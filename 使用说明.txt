12306 余票监控 · 配置工具
=====================================

【双击 12306Monitor.exe 打开界面】
改完需求 → 点「保存配置」→ 想让云端也跟着改就再点「同步到 GitHub」。


七个按钮分别是干什么的
-------------------------------------
保存配置          把你填的东西写到本文件夹的 monitor_config.json
                  （只影响这台电脑，云端不变）

立即扫描          立刻去 12306 查一轮，结果直接显示在下方黑框里。
                  （不发微信，纯查看，约 40~90 秒）

测试微信推送       发一条测试消息，收到说明推送链路是通的

同步到 GitHub     把配置推到云端仓库。需要 GitHub PAT（ghp_ 开头）+ 仓库名。
                  ⚠ 只在「部署平台 = github」时这才是让云端生效的那一步。

部署到腾讯云     把代码和配置打包上传到腾讯云函数，改完行程点这个才生效。
                  需要腾讯云 SecretId / SecretKey（填在右边凭据区）。
                  ⚠ 部署平台选 tencent 时，让云端生效靠的是这个按钮，
                    不是「同步到 GitHub」。

每日心跳         北京时间几点推一条「我还活着」。
                  因为只有出现新票才会推微信，不加这条你没法确认云端还在跑。
                  0 = 不推。改完要重新「部署到腾讯云」才生效。

---- 下面三个是云端监控的开关，不需要监控时用 ----
⚠ 这三个按钮管谁，由「部署平台」那一项决定：

  部署平台 = tencent  →  直接开关腾讯云函数的定时触发器（真正的开关）
  部署平台 = github   →  增删仓库里的定时任务文件（GitHub Actions）

关闭云端监控      停用云端：不再扫描余票、微信不再收到推送。
                  函数代码、配置全部保留，随时能重新打开。会先弹窗确认。

恢复云端监控      把定时触发重新打开，继续扫描并推微信。

查看云端状态      看云端现在是开着还是关着。


界面上每一栏怎么填
-------------------------------------
出发站        可接受的所有出发站电报码，逗号隔开
终点          最终目的地
换乘城市      第一次换乘允许在哪些站（可多个）
主干换乘站    fast 模式实际只扫这几个，一般取「换乘城市」的前两个就行

二次换乘      第二次换乘站，可填多个逗号隔开。不需要就留空
三次换乘      第三次换乘站，可填多个。留空 = 最多只算两次换乘
城际站        在这些站换乘只需预留 20 分钟（其余站 25~45 分）
最多换乘      1 / 2 / 3 档。填 3 且上面填了「三次换乘」才会有 4 段方案

换乘能到几次，看「填了几层」：
    只填换乘城市        → 最多 1 次换乘（2 段）
    填了「二次换乘」    → 最多 2 次换乘（3 段）
    再填「三次换乘」    → 最多 3 次换乘（4 段）
中间层可以整层跳过，所以直达、只换一次这些走法会同时保留，
不用为了看多种可能反复改配置。

举例：平顶山 → 郑州 → 焦作 → 焦作西
    换乘城市填 ZZF，二次换乘填 JOF，终点填 JIF
举例：想多试一条绕新乡的路
    二次换乘填 JOF,XXF，程序会把两条支线都穷举出来

日期 / 最早出发 / 最晚出发 / 最晚到换乘站 / 最晚到终点
              每天一行。这四个时间列是「你自己」的窗口，
              不填同行人时它就是唯一生效的一套。

  · 日期      点下拉直接选，里面是今天起 60 天；也可以自己手填 YYYY-MM-DD
  · 四个时间  都是「小时 + 分钟」两个下拉，00:00 ~ 23:59 全天任意时刻都能选，
              精确到分钟。只想限制整点就把分钟那个框留在 00。
              表示「不限」：把那格的两个框都选成「不限」（即清空）。
              「最晚到换乘站」用不到就留不限。

              ⚠ 日期必须和这一行的时间窗口成对出现。
                只选了日期但四个时间全是不限 → 全天扫描，票会非常多。


同行人（先一起坐一段，再各自走）
-------------------------------------
想和朋友搭同一趟车、中途各走各的，就在「同行人」这块点「+ 添加朋友」，
一行一个人，想加几个就加几个，随时能再加：

  称呼            随便起。推送里会显示「可与小明同行」
  他的终点        他最终要去的站电报码（用上面的查询框查，如 洛阳龙门=LLF）
  分手站(可留空)  限定在哪个站分开，多个用逗号隔开，如 ZZF,ZAF。
                  留空 = 不限，所有能同行一段的组合全都给你列出来
  共同段要几张票  含你自己。同一个席位等级够这个数，才算真能坐在一起
  他最晚到达      他到目的地的最晚时间，同样是「小时+分钟」两个下拉、全天可选，
                  可以跟你的完全不一样。
                  两框都选「不限」= 跟上面主终点的底线相同
  他最多换乘      他自己愿意倒几次车。0 = 他要直达，不限 = 能到就行。
                  你换几次跟他换几次互不相干

分手点不用你操心，程序自动把两边的路线从头比对，下面的组合全都能配出来：

  1. 换乘次数不同    你 1 次换乘到焦作西，他可以连换 3 次去别的地方
  2. 在换乘站分手    一起下车，各换各的车，之后各自再倒几趟都行
  3. 同一趟车上分手  你在郑州下车，他接着坐到新乡才下（谁先到谁先下）
  4. 有人直接到底    分手站就是他（或你）的终点，另一个还得接着换乘
  5. 一次带好几个人  你跟小明、小红一起坐到郑州，之后三个人各奔各的，
                     会合成一条推送给你，不会拆成好几条刷屏

判定规则：一起坐的那几段必须是同一趟车同一区间，且每段余票都够
「共同段要几张票」（只看商务/一等/二等，站票不算），
不够就标「⚠共同段余票不足 N 张」，这种不会推微信。

点「立即扫描」后，下方会分两组列出：
  ★ 命中你窗口的方案   你自己能走的（终点是你的终点）
  ★ / ○ 可同行方案    分开后各人怎么走、各人几点到。
                      ★ = 每个人都满足自己那条到达底线（会推微信）
                      ○ = 能同行但有人超时 / 坐不到一起（只记录，不推）
不加任何同行人 = 单人模式，行为和以前完全一样。

模式          fast ≈ 40 秒一轮（省额度，推荐）
              full ≈ 90 秒一轮（扫得更全，含买长乘短）

只推全程有座   勾上 → 无座方案不再打扰你


查车站代码
-------------------------------------
界面上有个「查车站代码」输入框，输中文站名回车就行。
全国 3404 个车站的电报码已经全部内置，不用自己往配置里加。

    洛阳     → LYF=洛阳  LDF=洛阳东  LLF=洛阳龙门
    焦作     → JOF=焦作  JIF=焦作西  WEF=焦作东
    平顶山   → PEN=平顶山  PDF=平顶山西
也可以反过来输三字母代码查站名，比如输 JIF → 焦作西。

常用站速查：
    平顶山 PEN    平顶山西 PDF   宝丰 BFF
    南阳 NFF      南阳东 NOF
    郑州 ZZF      郑州东 ZAF     郑州航空港 ZIF     郑州西 XPF
    焦作 JOF      焦作西 JIF     南阳寨 NYF


三个容易踩的坑
-------------------------------------
1. 日期和那一行的时间窗口必须成对填。
   只加日期不加窗口 → 那天一条都不会推，而且不报错。

2. 换了「换乘城市」，记得同步改「主干换乘站」，
   否则 fast 模式下新换乘站会被裁掉、扫不到票。

3. 换乘层数越多，组合爆炸越快：每层多填一个站，
   要扫的区间数是按乘法涨的（超过 70 条日志会告警、一轮会拖到几分钟）。
   真要多路线并行，建议把模式调成 fast，并靠「主干换乘站」压住规模。


关于 GitHub PAT
-------------------------------------
同步功能需要它。拿到方式：
github.com/settings/tokens → Generate new token (classic) → 勾 repo
填进界面的「GitHub PAT」栏即可，会存在本机 push_config.json，不上传。
同步完之后可以立刻去 GitHub 把 PAT 删掉，不影响已经建好的定时任务。


配置文件位置
-------------------------------------
本文件夹下的 monitor_config.json。
exe 和它必须放在同一个文件夹里，不要单独挪走 exe。
